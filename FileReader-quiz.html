一、基础与继承结构

01 单选

FileReader 面向的数据单位是？

正确答案 B

FileReader 把文件的字节按字符集解码成字符，面向 char 而不是 byte，所以它属于字符流，适合 .txt、.csv、.properties 这类文本文件。

02 单选

在继承链 Object → Reader → InputStreamReader → FileReader 中，FileReader 的直接父类是？

正确答案 C

继承链是 Object → Reader → InputStreamReader → FileReader：直接父类是 InputStreamReader，Reader 是祖父。FileInputStream 属于字节流那一支，和 FileReader 没有继承关系。

03 多选

FileReader 实现了下列哪些接口？

正确答案 A C D

文章「类继承结构」一节列出 Closeable、AutoCloseable、Readable 三个接口；前两个正是它能放进 try-with-resources 的原因。Serializable 与它无关。

04 多选

下列关于 FileReader 的说法，正确的是？

正确答案 A C D

FileReader 面向字符（A 对）、能放进 try-with-resources（C 对）、不该拿来读二进制（D 对）。它本身没有缓冲（B 错），通常要在外面套一层 BufferedReader。

二、构造方法与常用方法

05 单选

像 FileReader(String fileName, Charset charset) 这样能指定字符集的构造方法，从哪个 Java 版本开始提供？

正确答案 C

构造方法表里，两个带 Charset 的构造标注的版本都是 11。Java 11 以前要指定编码，只能改用 InputStreamReader。

06 多选

下列构造方法中，FileReader 真实存在的是？

正确答案 A B C

表里共五种入参：String、File、FileDescriptor，外加前两种带 Charset 的版本（Java 11+）。FileReader 没有接收 Path 的构造——要把 Path 用起来，可以走 Files.newBufferedReader(path) 这类 NIO API。

07 单选

reader.read() 的返回类型是什么，读到文件末尾时返回什么？

正确答案 A

read() 返回 int：读到的是该字符的数值，读到末尾返回 -1，所以循环条件写作 != -1。返回 String、末尾给 null 的是另一支 API——BufferedReader.readLine()。

08 单选

下面这段代码里，new String(buffer, 0, len) 的 len 表示什么？ 

char[] buffer = new char[1024];
int len;
while ((len = reader.read(buffer)) != -1) {
    System.out.print(new String(buffer, 0, len));
}

正确答案 B

read(char[]) 返回的是「本次实际读取的字符数」，最后一次通常小于数组长度。所以拼字符串时只取 [0, len) 这一段，不能把整个缓冲区都当成本次读到的内容。

09 单选

markSupported() 的返回值是？

正确答案 B

方法表里写得明白：markSupported() 恒为 false。想用 mark / reset，得换成支持它的流，比如 BufferedReader。

10 单选

transferTo(Writer out) 的返回类型与可用版本是？

正确答案 C

transferTo 把剩余字符全部写进 Writer，返回写入的字符数（long），标注版本是 Java 10+。文章「读取整个文件为字符串」的例子就是 transferTo 配 StringWriter。

11 单选

下面这段代码的问题是？

try (FileReader reader = new FileReader("demo.txt")) {
    String line;
    while ((line = reader.readLine()) != null) {
        System.out.println(line);
    }
}

正确答案 A

FileReader 本身没有新增方法，能用的是 read()、skip()、ready() 这些；readLine() 是 BufferedReader 的方法。正确写法是先套一层：new BufferedReader(new FileReader("demo.txt"))。

12 单选

getEncoding() 返回什么？

正确答案 A

getEncoding() 返回当前流使用的字符编码名称。「能否读取而不阻塞」是 ready() 的活，B 是它的干扰项；C、D 都不是这两个方法管的事。

三、字符编码

13 单选

从 Java 18 开始，JVM 的默认字符集是？

正确答案 B

JEP 400 从 Java 18 起把默认字符集统一为 UTF-8，不再随操作系统变化。Java 17 及以前，Windows 上常是 GBK，Linux / macOS 上常是 UTF-8。

14 单选

在 Java 17 及以前，同一份用默认字符集读文件的代码，换台机器就可能乱码，为什么？

正确答案 B

文章「字符编码问题」一节：Java 17 及以前，默认字符集由操作系统决定——中文 Windows 通常 GBK，Linux / macOS 通常 UTF-8。用默认字符集的代码换个平台就可能乱码。

15 单选

在 Java 8 上，要用指定编码（比如 GBK）读取文件，正确做法是？

正确答案 B

Java 11 以前 FileReader 不能指定编码，所以自己搭一段 InputStreamReader。A 那种构造形式并不存在（FileReader 不接收编码名），C、D 两个方法也不是真实 API。

四、对比与最佳实践

16 单选

要按行读取一个大文本文件，最合适的是？

正确答案 B

对比表里，BufferedReader + FileReader 有缓冲、支持 readLine()，正对「按行处理大文件」。逐个字符 read() 太慢；Files.readString 会把整个文件读进内存，不适合大文件。

17 单选

用 Java 11 一行代码把一个小文件完整读成字符串，该用哪个方法？

正确答案 B

Files.readString(path)（Java 11+）一行读完整文件。readAllLines 返回 List，Files.lines 返回惰性的 Stream，都不是「一个字符串」；D 是编出来的方法。

18 多选

下列哪些是文章给出的最佳实践？

正确答案 A B D

最佳实践第 1、2、5 条：try-with-resources 保证关闭；始终显式指定字符集；二进制文件交给 FileInputStream。C 不是文章的说法——缓冲区够用就好，开得过量只是白占内存。
